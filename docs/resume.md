## 一句话介绍

> 独立设计并实现「鲜达超市」线上生鲜超市系统：会员小程序逛超市下单，门店后台接单拣货配送，覆盖商品与组合商品、购物车、库存、订单全状态流转、实时新单提醒与经营报表，共 71 个 REST 接口。

## 简历条目（选 4～5 条，按目标岗位调整顺序）

- **鲜达超市 · 线上生鲜超市系统**（个人项目 | Java 17 / Spring Boot 2.7 / MyBatis-Plus / MySQL / Redis）
  采用 Maven 多模块（common / domain / server）+ 三层架构，划分商品、组合商品、类目、购物车、库存、订单、报表 7 个业务域，输出 71 个 REST 接口；用 Knife4j 按「门店运营端 / 会员端」分组维护在线接口文档。

- **库存中心（防超卖）**：以数据库为库存唯一事实源，用 `update ... set stock = stock - ? where id = ? and stock >= ?` 条件更新在订单事务内扣减，从根上杜绝超卖；Redis + Lua 做下单前库存快检（读-比较原子化）与读缓存，不足时回源 DB 复核避免脏缓存误拒；组合商品按 `bundle_item` 拆解到单品扣减。

- **幂等与并发控制**：下单引入客户端幂等令牌 + `trade_order.idempotent_token` 唯一索引，网络重试/连续点击只生成一笔订单，重复请求返回原订单；订单 6 个状态的全部跃迁改为条件更新（`where id = ? and status = ?`），并发接单只有一个请求成功，其余返回「状态已变更」。

- **库存回滚幂等**：取消、拒单、超时关单都会回滚库存，每次扣减/回滚写 `stock_log` 流水，回滚前用唯一键 `(order_id, product_id, type)` + `insert ignore` 判重，多入口同时取消也只回滚一次；关单逻辑下沉到 Service 事务方法，保证「改状态 + 回滚库存」同成功同失败。

- **缓存与读性能**：商品列表按类目缓存至 Redis（`freshmart:product:category:{id}`），写操作后按前缀失效；库存不进商品缓存（随订单实时变化），返回前补实时值；组合商品列表接入 Spring Cache 注解缓存（`bundleCache`）。

- **实时提醒与经营分析**：WebSocket 推送新单提醒与会员催单；MyBatis-Plus 聚合查询产出销售额趋势、会员增长、订单完成率、商品动销 Top10，基于 POI 模板填充导出近 30 天销售日报。

- **会员端小程序**（独立开发）：原生小程序 8 个页面（首页/详情/购物车/结算/订单/订单详情/地址/我的），统一请求封装（自动携带 JWT、401 清理登录态），对接自研 71 个接口，含库存售罄标记与下单幂等令牌。

- **门店运营后台**（独立开发）：零依赖原生 ES Module 单页应用，无 npm、无构建；hash 路由 + 8 个页面（工作台/订单/商品/组合商品/分类/员工/统计/设置），手写 SVG 折线、柱状、环形图与抽屉、弹窗、分页、骨架屏；nginx 反代 `/api/` 免跨域，401 自动清理登录态；后端配套补了「修改密码」「未读消息（待接单单量）」接口与商品/组合商品分页的规格、明细批量装配。

## ⚠️ 不要写的内容

以下能力当前**没有实现**，写上去在面试里是负资产：

- 消息队列（RabbitMQ / Kafka）、延迟消息（定时任务仍是每分钟轮询扫描）
- 分布式锁 / 微服务 / Spring Cloud / 集群高可用（本项目单体单机）
- 接口限流 / 熔断降级
- 真实微信支付、真实小程序前端分包、真实运力调度
- 分库分表、ES 搜索、多级缓存
- 任何"支撑 X 万 QPS / 百万订单 / 服务 N 家商户"的量级数字（没压测过）
- 后台**不要**写成 Vue / React / Element UI 技术栈（是原生 JS + 手写 SVG，没有 UI 框架）

> 库存、幂等、状态并发控制这次**已经实现并验证过**（见 `docs/技术亮点.md` 第四节），可以放心写。
