# 演示数据说明

仓库里的演示数据分两层：`sql/seed_catalog.sql` 是「最小可跑」的货盘，`sql/seed_demo.sql` 是「看起来像真在营业」的完整数据。两者都会先清空业务表再写入，可反复执行。

## 二、订单号规则

后端下单时生成 `FM + yyyyMMddHHmmss + 4 位随机数`，例如 `FM202605201325450090`。历史数据也按 `FM + 下单时间 + id 后四位` 对齐过，所以列表里订单号与下单时间能对得上。

## 三、怎么把数据换成这一套

```bash
# 建表
mysql -uroot -p < sql/freshmart.sql
# 生鲜货盘（21 商品 / 1 组合装）
mysql -uroot -p < sql/seed_catalog.sql
# 完整演示数据（会员、员工、4 组合装、37 订单、库存流水）
mysql -uroot -p freshmart < sql/seed_demo.sql
```

`seed_demo.sql` 用 `DELETE` + `INSERT` 实现，按 `trade_order_item → trade_order → stock_log → cart → bundle_item → bundle → product_spec → product → category → address_book → user → employee` 的顺序清理，不需要先删表。

## 四、页面能看到什么

- **工作台**：今日销售额、有效订单、完成率、客单价、新增用户；订单概览环形图（含「其他」切片，因为总览接口只给四个状态）；近 7 日销售额折线；待接单列表。
- **订单管理**：37 笔订单分页，按状态切 Tab，可接单 / 拒单 / 派送 / 完成 / 取消。
- **商品管理**：21 个商品，规格列显示规格条数，库存低于阈值显示告警色。
- **组合商品**：4 个组合装，包含单品的胶囊标签。
- **数据统计**：销售额趋势、订单量趋势、用户增长、销量 Top 10、导出 xlsx。

## 五、造数脚本（不在仓库里，供复现参考）

生成这批数据的脚本放在 `tools/`：

| 脚本 | 作用 |
| --- | --- |
| `gen_demo_data.py` | 插会员、员工、组合装，再用会员接口真实下单并走完状态机，最后摊时间、补库存 |
| `fix_demo_data.py` | 补 2 笔真正的待付款单（避免被超时任务关掉） |
| `fix_bundles.py` | 用真实商品名重设组合装明细，并把主图改成第一个单品的图 |
| `fix_future_orders.py` | 把摊时间时随机到「未来」的订单整体前移 |

数据是通过真实接口造出来的，不是直接写库，所以库存流水、订单明细、积分等副产物都是自洽的。
