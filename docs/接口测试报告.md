## 三、发现并修复的缺陷

### 1. 支付接口路径缺斜杠（严重）

- 现象：小程序点「支付」返回 404，订单一直卡在待付款。
- 原因：`OrderController` 的映射写成 `@PutMapping("payment")`，实际暴露为 `/user/orderpayment`；前端调的是 `/user/order/payment`。
- 修复：`freshmart-server/src/main/java/com/freshmart/controller/user/OrderController.java:66` 改为 `@PutMapping("/payment")`。

### 2. 默认地址接口路径缺斜杠（严重）

- 现象：结算页取不到默认地址。
- 原因：`AddressBookController` 写成 `@GetMapping("default")`，实际暴露为 `/user/addressBookdefault`。
- 修复：`freshmart-server/src/main/java/com/freshmart/controller/user/AddressBookController.java:94` 改为 `@GetMapping("/default")`。

### 3. 下单时空值拷贝异常（严重）

- 现象：请求体不带 `packAmount` 或 `tablewareNumber` 时，提交订单直接 500：
  `FatalBeanException: Could not copy property 'packAmount' from source to target; IllegalArgumentException: null`
- 原因：`TradeOrder` 里这两个字段是基本类型 `int`，`OrderSubmitDTO` 是 `Integer`，`BeanUtils.copyProperties` 把 null 拷给基本类型时抛异常。小程序和第三方调用方通常不传这两个字段。
- 修复：`OrderServiceImpl.submitOrder` 在拷贝前补默认值 0：

```java
//打包费和餐具数在实体里是基本类型，不传时补0，避免拷贝空值报错
if (orderSubmitDTO.getPackAmount() == null) {
    orderSubmitDTO.setPackAmount(0);
}
if (orderSubmitDTO.getTablewareNumber() == null) {
    orderSubmitDTO.setTablewareNumber(0);
}
```
